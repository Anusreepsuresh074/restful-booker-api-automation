## Open questions / follow-ups

- **`POST /auth` failure shape is confirmed** (rows 6–7): `200 OK` + `{"reason": "Bad credentials"}` for both wrong credentials and a missing `password` field — the API does not distinguish the two. Done: recorded in `context/api-auth.md`, matrix rows 4–5 and both tests now assert it exactly.
- **`PUT` with a partial body is confirmed** (row 19): `400 Bad Request`. Done: matrix row 19 and `test_update_booking_put_with_partial_body` assert `400` directly.
- **This API has no documented JSON error-response schema** for `403`/`400`/`404` — every error body observed in this run was plain text, not JSON (rows 19, 20, 22–24). Nothing to validate a schema against; noted as a structural gap in the API's own documentation, not a defect in the suite.
- **`additionalneeds`'s optionality was never exercised** — every test payload in this run supplied it, so whether the API accepts/echoes its absence is untested. Not a finding, just an uncovered branch.
- **No production/staging environment exists** to cross-check for environment-specific drift — this is the only real environment (`config/config.yaml`'s `dev`/`staging`/`prod` all point to the same URL).
